# 迭代纪律 / Iteration Discipline

> AI 视频的迭代最容易失控：改一堆东西、出问题了不知道是哪一步引入的。三条纪律 + 一种对比法，让迭代可归因、可回退、不浪费。

## 纪律 1：单变量迭代（Single-Variable Iteration）

**每次只改一个变量，其余全部冻结。**

- 一次反馈只对应一个修改点：改动作就只改"动作"层，不要顺手把光影也换了。
- 出问题了直接定位到上一次改的变量：画面崩了，就是刚改的那个变量引入的。
- 多问题要改：拆成多次迭代，一次一个，逐个验收。

```
❌ 反例：Clip 5 出问题 → 同时改了动作、镜头运动、光影 → 不知道是谁导致的
✅ 正解：Clip 5 出问题 → 只改动作 → 验证 → 仍不行 → 只改光影 → 验证
```

## 纪律 2：版本快照（Version Snapshot）

**每次迭代保留 prompt + 结果成对存档，可回退、可对比。**

- 快照内容：修改前的 Prompt、修改后的 Prompt、生成结果（图/视频）、验收结论。
- 命名建议：`clip05_v1`、`clip05_v2`…，与看板状态点对应。
- 用途：
  - **回退**：新版本更差，直接回退到上一版，不重新生成。
  - **对比**：A/B 需要两个快照并排看。
  - **归因**：翻快照就知道哪个变量在哪个版本被改过。

## 纪律 3：批量 vs 逐镜策略（Batch vs Per-Shot）

按序列长度选择策略，避免两种极端（逐镜太慢、全量返工太大）：

| 序列长度 | 策略 | 理由 |
|---|---|---|
| 短序列（< 6 镜） | **逐镜快速迭代** | 镜数少，逐镜改完即验收，成本可控、节奏快 |
| 中序列（6–10 镜） | 先全量生成，再按严重度集中改 | 全量出初版建立全局观，集中改高优先问题 |
| 长序列（> 10 镜） | **先全量再集中改** | 先看全片节奏与连贯性，避免在单镜上过度打磨 |

实战参考：《千禧信号·自复制AI反思》为 22 镜 4 场，采用"先全量再集中改"：先生成全部镜头建立全局，再按验收反馈集中修改最影响观感的镜头。

## 纪律 4：A/B 对比（A/B Testing）

**同一镜头的两个候选版本并排对比，二选一。**

- 适用：单变量改完仍不确定，或两个风格方向都想要时。
- 做法：保留两个快照，导演在导演台上并排看（或并排播放），选更优者，另一版归档不删。
- 注意：A/B 也遵守单变量——两个候选之间最好只差一个变量，否则对比无意义。

## 迭代流程图

```
验收不通过
    │
    ▼
定位问题（哪一镜/哪一层）
    │
    ▼
单变量修改（只动一个变量）
    │
    ▼
打快照（prompt + 结果存档）
    │
    ▼
重新生成 → 验收
    ├── 通过 → 下一镜 / 成片
    └── 更差 → 回退上一快照
```

## 常见误区

| ❌ 误区 | ✅ 正解 |
|---|---|
| 一次改多个变量 | 单变量，逐个验证 |
| 迭代后旧版本直接覆盖 | 版本快照存档，可回退对比 |
| 长序列一镜一磨 | >10 镜先全量，再集中改 |
| 拿两个差别很大的版本 A/B | A/B 只差一个变量才有对比意义 |
